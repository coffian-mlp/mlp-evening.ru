# 🦄 MLP-Evening: Поняшный Вечерок

**MLP-Evening** — это уютная и технологичная платформа для совместных киносеансов, созданная с любовью к дружбе и магии кода. Изначально проект задумывался для ламповых просмотров *My Little Pony: Friendship is Magic*, но его гибкость позволяет наслаждаться любым контентом в хорошей компании.

Ключевая особенность проекта — гибкая архитектура чата. Мы реализовали **гибридную систему**:
*   **Centrifugo (Go):** Мощный WebSocket сервер для масштабирования (тысячи онлайн).
*   **SSE (PHP):** Встроенный режим (Server-Sent Events) для работы "из коробки" без дополнительных зависимостей (для простых хостингов).

В комплекте идет умный генератор плейлистов, учитывающий историю просмотров, система ролей и удобная панель управления для Принцесс (администраторов).

## 🌟 Возможности

### 📺 Плеер и Просмотр
*   **Универсальный Плеер:** Поддержка вставки стримов через iframe (Twitch, GoodGame, YouTube и др.).
*   **Умный Плейлист:** Алгоритм генерации расписания на основе весов популярности и истории просмотров.
*   **Двусерийники:** Система знает, что некоторые эпизоды — это единое целое, и всегда ставит их парой!
*   **Расписание:** календарь (`/schedule.php`) с повторяющимися событиями. Завершение вечерка учитывает закреплённый плейлист и, при включённом флаге генерации, подготавливает следующую подборку.

### Плейлист и команды пожеланий

Подборка имеет бюджет **8 условных слотов**, а не обязательно 8 записей. Двусерийная история занимает два слота, всегда включается целиком и в порядке частей. Фильм использует свою каталожную стоимость. Выбор случайный без повторов: вес истории `(1 + 0.5 × V) / (1 + P)`, где `V` — активные пожелания обеих частей, `P` — общий счётчик просмотров. Просмотренные истории сохраняют положительный шанс. Это взвешенный выбор, а не гарантированный топ-8.

Новые команды работают с `!` и `/`; прежние команды сохраняют свои префиксы:

| Команда | Действие |
|---|---|
| `!хочу 100`, `!хочу Dragonshy`, `!хочу S01E07`, `!хочу с1э7` | Пожелание за точный эпизод |
| `!хочу <описание>` | Поиск с проверкой и кнопками подтверждения |
| `!желания` | Собственные активные пожелания |
| `!передумал <запрос>` / `!передумала <запрос>` | Отмена собственного пожелания |
| `!топ` | До пяти эпизодов по активным пожеланиям пользователей |
| `!плейлист` | Текущая опубликованная подборка |

Пользователь может выбрать до трёх разных эпизодов за календарные сутки Europe/Kaliningrad; повтор за тот же эпизод разрешён спустя 168 часов. Ограничения «раз в час» нет. Обновление не увеличивает число желающих от одного пользователя. Отмена убирает желание из веса, сохраняет историю и не возвращает квоту или cooldown. Пожелания частей двусерийника раздельны, просмотры общие. Желание исполняется при учёте показа, а не при попадании в подборку; пожелания после начала показа сохраняются для следующего раза.

Точное соответствие каталогу не требует поисковой модели. Свободное описание проходит отдельный поиск с источниками и независимую проверку; найденные варианты не записывают голос до нажатия кнопки. Общий запрос о персонаже, например `/хочу серию про тебя` или `/хочу серию про Шугар Белл`, может дать до трёх подтверждённых вариантов с появлением этого персонажа, заметным участием или характерной сценой; центральная сюжетная роль не обязательна. Если в запросе указаны конкретные события или исключения, поиск учитывает их. Выбор действует 15 минут, доступен владельцу и повторно проверяет санкции. Обычный текст «да» не подтверждает его. При сбое поиска можно использовать номер или точное название. Интерфейс кнопок общий для зарегистрированных команд; публичная страница каталога отложена.

Если предложен неверный эпизод, нажми «Не то, уточнить» и ответь с цитатой на предложение или вопрос Лиры, например `там была Рэрити`. Префикс `Уточнение:` необязателен: после перехода к уточнению достаточно обычного описания. Цитировать нужно сообщение Лиры, а не собственную команду; отказ с подробностями (`нет, не эта — там была Рэрити`) также продолжает поиск. Новый вариант требует подтверждения кнопкой, даже если уточнение содержит точный ID. Кнопка «Передумал» отменяет текущий выбор без изменения записанных пожеланий, квоты и cooldown; `/передумал <ID>` отменяет уже записанное пожелание. Без цитаты нужно явно обратиться к Лире и однозначно уточнить или отменить ровно один собственный подходящий выбор.

Цепочка действует 15 минут от начала: уточнения не продлевают срок. Сохраняются исходный запрос и принятые уточнения: суммарно до 600 символов, одно уточнение до 300, не более восьми. При отсутствии результатов можно уточнить снова или отменить выбор. Новый принятый `/хочу` заменяет собственный незавершённый поиск. Реплики формируются LLM по фактическому результату; при отключённом live-режиме, сбое или недостоверном ответе используется корректный резервный текст.

Ответы на команды используют обычную персону Лиры, память об авторе и общие сведения, а также разрешённые закреп и присутствие; история беседы и досье других присутствующих не добавляются. Адресат определяется сервером: допускается только его фактическое упоминание, а резервный ответ обращается к тому же автору. Запрос, уточнения и проверенные свидетельства помогают объяснить найденный вариант. Например, обычная цитата `Скорее твоё первое появление` может привести к подтверждённому первому эпизоду с пояснением фонового участия; уточнение первой заметной роли остаётся необязательным, голос требует кнопки. Известное альтернативное название первого эпизода проверяется по коду и каталогу, затем независимо по источнику.

После «Не то, уточнить» новый поиск ещё не выполнен: ответ запрашивает детали. Пустой завершённый поиск и сбой поиска описываются раздельно; сбой не означает отсутствие подходящих серий. При отключённом live-режиме, недоступном или недостоверном ответе сохраняется фактический fallback. Это исправление не требует новой миграции и сохраняет прежние привязки, сроки и защиту от повторного эффекта.

Завершение события с `use_playlist` автоматически отмечает весь закреплённый снимок просмотренным один раз. При `generate_new_playlist` публикуется следующий список; флаги независимы, событие только с генерацией не начисляет просмотры. Прерванный вечер исправляется в Дашборде → «Эпизоды»: выбрать сохранённый снимок и конкретный показ, оставить отмеченными только целиком показанные истории. Уже начатое событие сохраняет прежний снимок; явная пересборка до начала обновляет будущую привязку с аудитом. Неизвестный прошедший показ без доказанной привязки требует внимания, а не получает произвольный текущий список.

Новые реплики Лиры формулирует LLM; код проверяет факты и права. При недоступности модели или неверных фактах используется фактический резервный ответ. Команды поступают в очередь и работают с резервными ответами при выключенном ИИ.

### 🤖 Лира-Бот (AI Ассистент)
*   **Умные ответы:** Интеграция с целым созвездием LLM-провайдеров: OpenAI, OpenRouter, RouterAI, YandexGPT, GigaChat (с автоматическим fallback — если один источник магии иссяк, Лира пробует следующий).
*   **Очередь заданий (BOT-QUEUE):** Ответы бота готовятся в фоновой очереди (`llm_jobs`) единым воркером — чат не тормозит, даже когда все пони зовут Лиру одновременно. Режимы воркера: daemon / cron / inline (умная деградация).
*   **Зрение (Vision):** Лира видит картинки в чате! Изображения аккуратно сжимаются и отправляются vision-моделям.
*   **Реакции:** Лира умеет ставить эмодзи-реакции на сообщения, как настоящая пони.
*   **Контекст и Память:** Бот помнит историю сообщений и отвечает с учетом контекста беседы.
*   **Спонтанность:** Бот умеет сам инициировать диалог, прерывая неловкое молчание, но не разговаривает сам с собой. Отвечает только когда к нему действительно обращаются.
*   **Интеграция с расписанием:** По команде `/расписание` или `/schedule` бот изучает календарь и выдает анонс ближайшего события, а также сам делает авто-анонсы за 60 и 15 минут до старта!
*   **Динамические команды:** Собственный фреймворк команд бота с управлением из Дашборда.
*   **Гибкие настройки:** Управление промптом, токенами и поведением бота прямо из панели администратора.
*   **Защита заклинаний:** Санитизация ответов — системные инструкции бота никогда не просачиваются в чат.

### 💬 Магический Чат (Zero-Dependency Realtime)
*   **Мгновенная доставка:** Технология SSE обеспечивает живое общение без задержек.
*   **Markdown и Форматирование:**
    *   Жирный, *курсив*, ~~зачеркнутый~~, `код` и `> цитаты`.
    *   Спойлеры `||скрытый текст||` для защиты от лишней информации.
*   **Медиа-магия (Embeds):** Автоматическое превращение ссылок в картинки и видео. Загрузка файлов Drag & Drop и вставка из буфера обмена (Paste).
*   **Удобство общения:**
    *   **Упоминания:** Нажми на имя пони или напиши `@Ник`, чтобы позвать друга.
    *   **Цитирование:** Красивые карточки цитат с переходом к оригиналу.
    *   **Редактирование:** Возможность исправить опечатку или удалить сообщение (Soft Delete).
    *   **Реакции:**
        *   16 реакций: 👍, ❤️, 😂, 😮, 🔥, 🎉, 😎, 🤔, 😐, 😢, 👀, 👎, 💀, 🤡, 💯 и 💩. Последние четыре добавлены в MLP-360; прежние ключи сохранены.
        *   **Smart Tooltip:** Наведи на реакцию, чтобы увидеть список пони, которые её поставили (с их аватарками!).
        *   Мгновенное обновление счетчиков у всех пользователей.
        *   Даже Лира-бот ставит реакции!

### 🦄 Режимы работы чата

Проект поддерживает два драйвера для работы чата, переключаемых в `config.php`:

1.  **Centrifugo (Рекомендуется)** 🚀
    *   Использует WebSocket для мгновенной доставки сообщений.
    *   Выдерживает тысячи одновременных подключений.
    *   Снимает нагрузку с PHP и базы данных.
    *   **Инструкция по установке:** [DEPLOY_CENTRIFUGO.md](DEPLOY_CENTRIFUGO.md)

2.  **SSE (Server-Sent Events)** 🐢
    *   Работает "из коробки" на голом PHP без дополнительного ПО.
    *   Использует постоянные HTTP-соединения.
    *   **⚠️ Внимание:** Этот режим может работать нестабильно на слабых серверах или виртуальном хостинге (возможны задержки сообщений из-за буферизации Nginx/Apache, блокировок сессий или таймаутов).
    *   Мы добавили этот режим для совместимости, но рекомендуем использовать Centrifugo для стабильной работы.

### 🛡️ Модерация и Администрирование
*   **Иерархия:** Система ролей (Пользователь, Модератор, Администратор).
*   **Безопасность:**
    *   Восстановление пароля через Email (SMTP) с генерацией безопасных токенов.
    *   **Защита от подбора паролей (Brute-force):** Умная блокировка по IP. При подозрительной активности система предлагает пройти "Испытание Гармонии" (капчу), а при настойчивых атаках — временно блокирует доступ.
*   **Инструменты Порядка:** Бан (Ban), Мут (Mute - временная тишина), Очистка (Purge).
*   **Авторизация при бане:** вход по паролю, через связанную социальную учётную запись и remember-cookie разрешён. Чат публичный и доступен для чтения; действующий бан запрещает отправку сообщений с уведомлением о причине и сроке санкции. Бан и мут проверяются до antiflood. Настройка скрытия чата от гостей пока не реализована.
*   **Контекстное Меню:** Быстрые действия по правому клику на сообщении.
*   **Всевидящее Око (Audit Log):** Подробный журнал действий модераторов.
*   **Debug Mode:** Включение отображения ошибок PHP (`display_errors`) прямо из админки для быстрой отладки на лету.
*   **Дашборд:** Управление пользователями, плейлистами и настроек сайта в одном месте.

## 🛠️ Технологии

*   **Backend:** PHP 8.3 (Extensions: `curl`, `opcache`) — чистая магия, никаких фреймворков.
*   **Frontend:** HTML5, CSS3 (Flexbox/Grid), jQuery (локальный) — легкость и скорость.
*   **Database:** MySQL 8.0 — надежное хранилище знаний.
*   **Container:** Docker & Docker Compose — развертывание одной командой.

## 🧠 Архитектура Ядра (src/)

Сердце проекта — набор PHP классов, реализующих всю бизнес-логику без использования сторонних фреймворков.

### 🧩 Компоненты (src/Components/)

Мы используем модульную архитектуру, вдохновленную Bitrix. Каждый функциональный блок — это независимый компонент со своей логикой, шаблонами и стилями.

*   **`Auth`**: Модальные окна входа, регистрации и восстановления пароля.
*   **`Chat`**: Основной компонент чата. Поддерживает режимы `embedded` (встроенный) и `popup` (отдельное окно).
*   **`DbAdmin`**: Мощный инструмент для управления базой данных прямо из админки (CRUD, фильтрация, экспорт CSV).
*   **`Profile`**: Модальное окно настроек пользователя (аватар, цвет ника, смена пароля).
*   **`VideoPlayer`**: Обертка для плеера стрима.
*   **`Admin*`**: Семейство компонентов панели управления (`AdminUsers`, `AdminPlaylist`, `AdminHistory` и др.).

### 🏛️ Основные Классы (src/Core/ & src/)

### `Core` (src/Core/)
Фундамент модульной системы.
*   `Application`: Главный класс-распорядитель (Singleton). Управляет заголовками, подключением CSS/JS и компонентов.
*   `Component`: Базовый абстрактный класс для всех компонентов. Обеспечивает логику подключения шаблонов.

### `Database`
Обертка над MySQLi, реализующая паттерн **Singleton**. Гарантирует единое подключение к базе данных на протяжении всего скрипта.
*   `getInstance()`: Получение экземпляра.
*   `getConnection()`: Прямой доступ к объекту `mysqli`.

### `Auth`
Статический класс для управления сессиями и безопасностью.
*   `check()` / `requireLogin()`: Проверка авторизации.
*   `isAdmin()` / `isModerator()`: Проверка прав доступа.
*   `generateCsrfToken()` / `checkCsrfToken()`: Защита форм от CSRF-атак.

### `ConfigManager`
Управление глобальными настройками сайта (хранятся в `site_options`).
*   `getInstance()`: Получение экземпляра (Singleton).
*   `getOption($key, $default)`: Получение значения настройки.
*   `setOption($key, $value)`: Сохранение настройки.

### `OnlineManager`
Управление статусом онлайн и подсчетом гостей.
*   `beat($sessionId, $userId, ...)`: Обновление времени последней активности (Heartbeat).
*   `getOnlineStats($window)`: Получение списка пользователей и количества гостей за последние N минут.
*   `cleanup($minutes)`: Очистка старых сессий из базы.

### `CaptchaManager`
Управление игровым процессом "Испытание Гармонии" (капчей).
*   `start()`: Инициализация сессии капчи (выбор случайного пони).
*   `checkAnswer($answer)`: Проверка ответа и переход к следующему этапу (Текст -> Картинка -> Спайк).

### `CentrifugoService`
Обертка для работы с HTTP API сервера Centrifugo.
*   `publish($channel, $data)`: Отправка сообщения в канал.
*   `broadcast($channels, $data)`: Массовая рассылка.
*   `generateToken($userId)`: Генерация JWT токена для клиента.

### `Mailer` & `SimpleSMTP`
Отправка транзакционных писем (например, сброс пароля).
*   `Mailer::sendPasswordReset($email, $link)`: Формирование и отправка письма.
*   `SimpleSMTP`: Легковесная реализация SMTP клиента на сокетах (без PHPMailer).

### `UserManager`
Управление пользователями, их профилями и настройками.
*   `getAllUsers()`: Получение списка пользователей с `JOIN`-ом их настроек (цветов, аватарок) из таблицы `user_options`.
*   `updateUser($id, $data)`: Умное обновление — автоматически распределяет данные между таблицей `users` и `user_options`.
*   `banUser()` / `muteUser()` / `logAction()`: Логика наказаний и ведение журнала действий (Audit Log).

### `ChatManager`
Логика чата, обработка сообщений и Markdown.
*   `getMessages($limit)`: Выборка сообщений для SSE потока (с обработкой удаленных и отредактированных).
*   `addMessage()`: Добавление сообщения с проверкой статуса пользователя (не забанен ли, нет ли мута) и анти-спам таймером.
*   `purgeMessages()`: Массовое удаление (Soft Delete) сообщений нарушителя.

### `EpisodeManager`
Каталог эпизодов, пожелания пользователей и сохранённые подборки.

- `getAllEpisodes()` читает актуальные счётчики из БД без файлового кеша.
- `getEveningPlaylist()` / `getSavedPlaylist()` возвращают опубликованный снимок; чтение и голосование не пересобирают его.
- `regeneratePlaylist()` публикует новую подборку; предыдущий состав сохраняется.
- `wish()` / `cancelWish()` ведут авторство, историю, квоты и отмену пожеланий. `voteForEpisode()` сохранён как административный адаптер старых агрегатных голосов.
- `finishOccurrence()` атомарно учитывает конкретный показ и подготовку следующей подборки; `correctCompletion()` исправляет состав показанного без удаления истории.
- `PlaylistLifecycle` связывает календарные события со снимками и обрабатывает завершение независимо от доступности ИИ.

### API интерактивных команд

Новые действия выполняются через POST `/api.php`; формат ответа сохраняет `success` и `data`.

| Action | Поля запроса | Доступ и результат |
|---|---|---|
| `get_command_interaction` | `interaction_id`, `message_id` содержащего сообщение | Публичное чтение labels/state/expiry/can_act; без executable payload, чужого private result и CSRF |
| `act_command_interaction` | `interaction_id`, `option_key`, `csrf_token` | Авторизованный владелец; сервер проверяет права, исходное сообщение и срок; `data.outcome` сохраняется для retry |
| `mark_watched` | `snapshot_id`, `csrf_token` | Администратор; конкретный снимок/привязанный показ вместо прежнего `ids` |
| `correct_playlist_completion` | `snapshot_id`, `completion_key`, `story_ids[]`, уникальный `operation_key`, `csrf_token` | Администратор; история корректировки целых stories. Для пустого состава передать пустой массив или не передавать `story_ids` |

Identity пользователя задаёт сессия; клиент не передаёт handler/payload/episode ID для кнопки. Типы зарегистрированы кодом в composition root. `CommandInteractionManager` принимает registry с callback `permission(actorId,payload)` и `execute(actorId,payload,operationKey)`, returning `{status,code,facts}`; `execute` работает в общей транзакции и не вызывает HTTP/LLM. Последующая доставка реплики ставится в очередь после commit. Renderer один для embedded/popup, quotes/pins не создают исполнимых копий. Добавление новой команды должно расширять registry, а не копировать UI голосования.

### `StickerManager`
Управление коллекцией стикеров.
*   `getAllPacks()`: Список коллекций (паков).
*   `createPack()` / `updatePack()` / `deletePack()`: Управление паками (с автоматическим удалением файлов).
*   `addSticker()`: Добавление стикера.
*   `importFromZip()`: Магия массовой загрузки из архива с автоматической транслитерацией и генерацией кодов.

### `UploadManager`
Обработка загружаемых файлов.
*   `uploadFromPost()`: Валидация и сохранение файлов из форм.
*   `uploadFromUrl()`: Скачивание изображений по ссылке (для аватарок).

### `SocialAuthService` (src/Social/)
Единая точка входа для авторизации через социальные сети.
*   `handleLogin()`: Умная логика входа:
    1.  Если аккаунт привязан -> Вход.
    2.  Если пользователь уже вошел -> Привязка соцсети к профилю.
    3.  Если новый пони -> Автоматическая регистрация и вход.
*   `TelegramProvider`: Реализация проверки подписи виджета Telegram (Hash Validation).

### 🔮 Магия Лиры (src/LLM/)
Отдельное крыло библиотеки, где живет вся магия AI-бота.
*   `LLMManager`: Ядро бота — собирает контекст беседы, выбирает провайдера, применяет промпты.
*   `LLMProviderInterface` + провайдеры: `OpenAIProvider`, `OpenRouterProvider`, `RouterAIProvider`, `YandexGPTProvider`, `GigaChatProvider`, `CliUtilityProvider`. Новый источник магии = новый класс, ядро не трогаем!
*   `BotDispatch`: Продюсер — решает, отправить задание в очередь или ответить сразу (inline).
*   `JobQueue` + `BotWorker`: Очередь заданий (`llm_jobs`) и единый воркер (daemon / cron / inline). Умеет склеивать несколько упоминаний в один ответ и отвечать с «живой» задержкой.
*   `ReplyPolicy` / `ResponseSanitizer` / `ReactionParser` / `VisionFormatter`: Пост-обработка — когда молчать, как чистить ответ, как ставить реакции и как показывать боту картинки.
*   `XrayManager`: VLESS-прокси для доступа к заморским источникам магии (см. `src/LLM/README_VLESS.md`).

## 🚀 Как запустить (Локально)

1.  Убедитесь, что у вас установлен **Docker** и **Docker Compose**.
2.  Клонируйте этот репозиторий.
3.  Создайте конфигурационные файлы:
    ```bash
    cp config.sample.php config.php
    cp centrifugo_config.sample.json centrifugo_config.json
    ```
4.  Запустите магию одной командой:
    ```bash
    docker-compose up -d --build
    ```
4.  Сайт откроет свои двери по адресу: `http://localhost:8080`

### 🔑 Доступы
*   **MySQL:** Конфигурация в `docker-compose.yml` и `config.php`.
*   **Сайт:** Регистрация открыта для всех пони.
*   **Админка:** Доступна пользователям с ролью `admin` (кнопка 🔧 в меню).
