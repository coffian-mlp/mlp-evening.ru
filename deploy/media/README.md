# Собственный эфир: MediaMTX и HLS

Дополнительный модуль для собственного Linux-сервера. Основной сайт сохраняет поддержку внешнего плеера. Пилот: один поток H.264/AAC из OBS, одно качество, без перекодирования и записи. Видео передаётся отдельным медиасервисом; PHP обслуживает настройки и административную диагностику.

## Компоненты и ограничения

- MediaMTX 1.21.3, официальный Linux amd64 архив. Установщик проверяет SHA-256 `0a2ea7eba96023631efa1bea7804823a9145b043b6646a8a05798d4ac24ed635`.
- RTMPS TCP 1936: приём с TLS и отдельным ключом; обычный RTMP отключён.
- HLS 127.0.0.1:8898: nginx публикует только `/live/` через HTTPS. API 8897 и метрики 8899 доступны только через loopback. Порт FASTPANEL 8888 не используется.
- Единственный путь: `evening`. Публикация без ключа, публикация в другие пути и замена активного вещателя запрещены. Просмотр публичный.
- Сервис `mlp-mediamtx` запускается отдельным непривилегированным пользователем. MemoryHigh 256 MiB, MemoryMax 384 MiB, swap запрещён, CPUQuota 75% одного ядра, Go soft limit 192 MiB. Это защитные лимиты, не прогноз фактического потребления.
- HLS: пять сегментов по минимум две секунды, максимум 8 MiB на сегмент; задержка зависит от OBS, ключевых кадров, сети и буфера зрителя. `maxReaders` ограничивает медиачитателей и не является точным лимитом зрителей HLS.
- Hls.js 1.7.3 хранится локально с лицензией Apache-2.0. Используется полная сборка для раздельных дорожек видео и звука MediaMTX. Safari использует нативный HLS при наличии; остальные поддерживаемые браузеры — Media Source Extensions. Управление громкостью и переподключение находятся в компоненте VideoPlayer. Для собственного видео разрешение на сторонний плеер не требуется.

## Установка

Требуются Ubuntu 24.04 amd64, root-доступ, nginx с действующим HTTPS и системный Python 3. Docker и FFmpeg на сервере для прямой раздачи не нужны.

1. Уточнить пути действующего сертификата и ключа nginx. Установщик не меняет их и передаёт сервису копии через systemd LoadCredential.
2. От root выполнить `sh deploy/media/install.sh mlp-evening.ru /путь/к/сертификату.crt /путь/к/ключу.key fastuser`.
3. Добавить блок `/live/` из `deploy/nginx/mlp-evening.conf` в nginx сайта. Обязательны правила proxy_redirect и proxy_cookie_path: MediaMTX проверяет поддержку cookie через перенаправление, которое должно оставаться в префиксе /live/. Перед изменением сохранить прежний include; выполнить `nginx -t`, затем `systemctl reload nginx`. Не заменять независимые правила приложения.
4. Разрешить входящий TCP 1936 в облачном firewall, если он включён. Не публиковать 8897–8899. Установщик не изменяет firewall.
5. Проверить `systemctl status mlp-mediamtx`, затем в дашборде открыть «Настройки плеера» → «Проверить поток». Публичный источник остаётся внешним до явного сохранения выбора.

Повторный запуск установщика при существующем конфиге останавливается. Он не вращает ключ и не перезапускает работающий эфир. Для обновления: сохранить конфигурацию, дождаться отсутствия вещателя, проверить новую версию и заменить бинарник с проверкой официальной контрольной суммы.

## Подключение OBS

1. В дашборде: «Настройки» → «Настройки плеера» → «Подключение OBS» → «Получить параметры OBS». Только администратор получает сервер и ключ; значения отсутствуют в исходном HTML страницы.
2. OBS → Настройки → Трансляция → сервис «Настраиваемый». Сервер: `rtmps://mlp-evening.ru:1936`. Ключ: скопировать целиком из дашборда, включая имя пути и параметры авторизации. Не публиковать ключ в чате или скриншоте.
3. Первый тест: H.264, AAC, 1920×1080 или 1280×720, 24/30 кадров/с, CBR 6000 Кбит/с, ключевой кадр каждые две секунды, звук 160–192 Кбит/с. Более поздний подбор битрейта не требует изменения сервера.
4. Нажать «Начать трансляцию», открыть административный предпросмотр `/stream-preview.php`. Проверить изображение, звук, громкость, телефон и переподключение после остановки/возобновления OBS. Автовоспроизведение начинается без звука; включение звука выполняет зритель.
5. Для пробного просмотра другими участниками выбрать «Собственный эфир — HLS» в настройках плеера и сохранить. Для возврата выбрать внешний источник; прежняя ссылка Twitch сохраняется. Зрителям нужно обновить страницу.

Чистая установка сайта без медиамодуля показывает понятную ошибку диагностики и продолжает использовать внешний плеер. Адрес HLS допускает только локальную форму `/live/ИМЯ/index.m3u8`; внешний медиасервер можно разместить за тем же nginx-прокси.

## Секреты и обслуживание

Ключ хранится вне webroot и Git: `/etc/mlp-evening/stream-publish.json`, root:fastuser 0640. Для другого размещения предусмотрена переменная `.env` `SELF_HOSTED_STREAM_CREDENTIALS`. Конфигурация MediaMTX — root:mlp-media 0640. Файл с параметрами OBS является секретом; включать его только в защищённую резервную копию.

После обновления сертификата ежедневный таймер в 04:15 UTC сравнивает его с загруженной копией и перезапускает только медиасервис при отсутствии активного вещателя. Если эфир идёт или API недоступен, обновление откладывается. При смене самих путей сертификатов обновить LoadCredential и `/etc/mlp-mediamtx/tls-certificate-source`. Проверка: `systemctl list-timers mlp-media-certificate.timer` и `journalctl -u mlp-media-certificate.service`.

Диагностика: `journalctl -u mlp-mediamtx.service`, `systemctl show mlp-mediamtx.service -p MemoryCurrent -p MemoryPeak -p NRestarts`, `curl --noproxy '*' http://127.0.0.1:8899/metrics`. При ошибках ключа не включать подробное логирование с URL и параметрами авторизации. Показатель готовности входного потока не доказывает успешный просмотр; предпросмотр с декодированием и проверка со стороны зрителя обязательны.

Пилот не начисляет просмотры эпизодов и не отправляет сообщения Лиры при появлении потока. Связь доступности видео с расписанием и оповещениями — отдельная задача.
